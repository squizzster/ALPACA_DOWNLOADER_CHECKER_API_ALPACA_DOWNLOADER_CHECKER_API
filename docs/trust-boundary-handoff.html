Trust-boundary implementation handoff

Read this before continuing the boundary audit or changing handoffs. This is the repository copy of the implementation review, including the exact remaining scope. The work changes trust boundaries, handoff retention, producer ingress validation, progress carry-through and acknowledgement bookkeeping. Lineage rules, correlation policy, conservative reuse gates and retry policy are unchanged.

Twenty-one of the twenty-six findings are fixed and verified. One remains partial, one remains open, one has its supported scope clarified, and two retain their existing evidence/freshness policy. The rows below distinguish implementation closure from remaining requirements.

Authorities and continuation

AGENTS.md owns storage trust and permissions. Architecture identifies the producer for each boundary. Technical contracts owns the artifact, lock and recovery guarantees. Development owns verification and rule-change requirements. CLI reports explains heartbeats and debug traces.

Before changing a handoff, identify its producer, selecting artifact, scope, lifetime and actual invalidation condition. Preserve an accepted value until one of those conditions changes. Retain the owning regressions that forbid repeated upstream reads and exercise newer generations, incomplete publication and expired authority. In particular, a passing suite does not close the remaining historical attribution or every coverage gap.

Verified behavior

  • Selected reader and offline-evidence receipt reads fell from three to one.
  • Unchanged and metadata-only lineage work no longer opens the completed summary endpoint validator.
  • Recovery retains accepted sources, notices and journal-provided receipts through acknowledgement.
  • Locked pricing views are retained for their lifetime; acknowledgement batches bind store, process, thread and transaction lifetime, reject newer obligations and roll back before commit.
  • HTTP producers reject credential-bearing redirects and malformed metadata completion envelopes.
  • Heartbeats retain accepted work estimates, completion counts, selected scope and request totals. Daily updates estimate remaining known pricing requests from those plans and observed wall-time throughput; phase estimates use existing completed/selected counts. Reporting adds no store/provider reads or timing cache, keeps uncertainty explicit and does not equate an exhausted request estimate with command completion.
  • Compact planning rejects ticker-owner I/O. Execution aborts before unselected owner-path access; completed metadata and serving component selections explicitly extend its allowed scope.
  • Eligible summary members complete approved maintenance before discovery advances dependencies; later phases reuse only matching summary entries and pricing generations within the same operation.
  • Endpoint checks retain exact session windows. Execution consumes the accepted validator and comparison, while independent new-output confirmation and generation checks remain active.
  • Daily checks compare the first and latest fully adjusted rows from summary format 3. A changed endpoint selects full retained-span replacement; matching endpoints approve only missing-session acquisition.
  • Lineage fallback retains decoded pricing partitions; nested metadata needs share a completed containing interval; single-source observation selection skips unused multi-source preparation.

The linked owning regressions use real producer pipelines with synthetic stores and provider doubles. They assert both completed results and forbidden redundant work, with generation, mapping, scope, pagination, concurrent-publication and interruption counterexamples. Forked-process SIGINT tests restart after a dependency request and a pending pricing journal, complete pricing/lineage/serving, and preserve the resulting histories. Redirect regressions exercise both actual clients over loopback HTTP. Runtime changes are recorded in their owning changelogs; persisted pricing and lineage contracts are preserved. The summary's format upgrade requires an explicit offline rebuild and has legacy interruption coverage.

Shared HTTP execution now subdivides bars and corporate-action logical requests into balanced batches of at most 1,000 symbols, exhausting pagination independently and withholding results until the whole action completes. Endpoint retry/rate/timeout policies and credential-target checks remain in force. The API plan contract defines the completion and accounting boundary. test_alpaca_http_batching.py exercises both real adapters with synthetic HTTP responses, the 3,386-symbol daily check, empty histories, retries, malformed later batches, 414 fallback and logical-action failure. test_alpaca_data_api_solver.py retains ordering, delivery and response-lifetime regressions. These checks do not establish production latency or close F15's broader coverage limits.

Reporting regressions in test_alpaca_update_eta.py cover concurrent request measurement, failed calls, changed request scope, counter resets, heartbeat cadence and synthetic update parity through serving. The estimate covers known pricing requests and separately measured phases; unselected future work and unmeasured local stages remain outside its numerical range.

Live verification and limits

The subsequent authorized update with debug and without a separate plan run completed through the November 2, 2026 session in 1,256.5 seconds, with zero failures and zero pending work. It made 2,672 pricing and 449 metadata HTTP requests. The 2,560 late-bar probes occupied about sixteen minutes (76 percent of the run). All 9,422 append outcomes were unchanged; the live comparison selected one effective pricing correction. This same-cutoff run is not a controlled comparison with the earlier four-hour update.

The debug trace closed all 9,756 started spans without a reported error or abort. Raw traces, full runtime results, experiments and the original source inventory remain outside Git. They are observations of the exercised paths, not proof of every input or interleaving. The earlier four-hour run still lacks its own diagnostic trace.

The advancing-cutoff trace exposed F18–F23 and ended on requested SIGINT during dependency acquisition, with exit code 130 and no unclosed spans. That trace establishes the interrupted stage, not successful recovery. Recovery of the changes below is verified synthetically. A production restart completed journal recovery and compact selection, then exhausted six attempts on its first 3,386-symbol exact endpoint batch. An identical read-only request returned HTTP 504 with a backend timeout; smaller requests completed. A replay using the enlarged client timeout still received the backend failure before that timeout. The updater was interrupted cleanly before pricing or lineage publication. That attempt did not establish production completion; a controlled live throughput comparison remains unperformed.

A bounded read-only live MSGS check exercised exact endpoint planning in all eight retained views: sixteen requests returned sixteen matching rows. The revised daily first/latest check then used only the fully adjusted view: two requests returned two matching rows, with no pricing publication. This verifies those provider requests and comparisons, not universe throughput or every security.

An interrupted advancing-cutoff run checked 9,413 symbols: 9,354 matched, 26 differed and 33 had missing endpoints, with no request failures. Controlled read-only replays reproduced all 33 first-endpoint omissions in their original rosters; reduced rosters returned all 66 first/latest observations. The original run did not save response bodies. One controlled two-symbol case isolated companion-dependent suppression. The failed check also discarded completed comparisons, reproduced through a synthetic complete update. F25–F26 cover those defects and adjacent partial-publication cases. A subsequent debug update with these repairs completed pricing, lineage and serving through November 3, 2026, with zero failures and pending work and all 33 omissions recovered. Its trace closed every started span. That run also exposed a bounded loss of accepted metadata between recovery and discovery; that repeated acquisition remains a coverage gap under F15.

The pricing transport contract distinguishes the client socket timeout from an earlier provider failure. Owning regressions exercise slow paginated responses without redundant requests, bounded timeout retries and preserved HTTP 504 classification: test_alpaca_pricing_download.py and test_alpaca_pricing_rate_limit.py. Retry errors and cooldowns are not exposed by the existing heartbeat; the debug request exit retains the attempt count but can omit a wrapped HTTP status. A healthy heartbeat alone does not establish provider progress.

F26fixed and verifiedPeer failures discard completed comparisons and publications

Accepted matching and differing comparisons survive peer failures within the operation, bound to summary and generation. Differences remain correction work; renewed correction obligations invalidate append approval. Changed generations, stale summary tokens and restart cannot inherit stale comparisons. Genuine failures keep the overall update incomplete.

Owning regressions: test_alpaca_update_handoff_regressions.py, test_alpaca_update_everything.py, test_alpaca_approval_handoffs.py.
