Trust-boundary implementation handoff

Read this before continuing the boundary audit or changing handoffs. This is the repository copy of the implementation review, including the exact remaining scope. The work changes trust boundaries, handoff retention, producer ingress validation, progress carry-through and acknowledgement bookkeeping. Lineage rules and correlation policy are unchanged; reuse consumes completed pricing and metadata handoffs.

Twenty-six of the thirty findings are fixed and verified. One remains partial, one remains open, one has its supported scope clarified, and one retains its freshness policy. The rows below distinguish implementation closure from remaining requirements.

Authorities and continuation

AGENTS.md owns storage trust and permissions. Architecture identifies the producer for each boundary. Technical contracts owns the artifact, lock and recovery guarantees. Development owns verification and rule-change requirements. CLI reports explains heartbeats and debug traces.

Before changing a handoff, identify its producer, selecting artifact, scope, lifetime and actual invalidation condition. Preserve an accepted value until one of those conditions changes. Retain the owning regressions that forbid repeated upstream reads and exercise newer generations, incomplete publication and expired authority. In particular, a passing suite does not close the remaining historical attribution or every coverage gap.

The separate standalone Bloodhound converter consumes completed CSV exports or legacy histories; it does not participate in pricing, lineage or serving publication. Its current CSV regressions assert selected-only consumption, one read per selected boundary/payload and no upstream checksum recalculation. CSV schema 2 carries the opened catalogue's completed observed-label ranges intact, including for filtered exports. The converter projects their inclusive endpoints once into row labels shared across all eight views; it does not replay ownership evidence, audit descriptive ticker membership or reopen the source catalogue. Missing schema-2 handoffs fail before payload reads; actual ambiguity remains explicit and may be resolved by supplied dated metadata. Schema-1 compatibility scopes older ownership intervals to the full input range and actual sessions before interpreting them. The regressions cover schema/generation mismatch, missing and empty handoffs, overlapping labels, exact endpoints, one-session conflicts and forbidden repeated selection, source authentication or boundary reads. The CSV producer regressions also cover an end-to-end export/conversion and retain publication interruption and source-read guards. Its known publication and validation limits are separate from the thirty engine findings below. Importing the app does not close those limits or extend the engine's publication guarantees to it.

The operation handoff regressions reject repeated summary/tail validation, per-target append compilation, locked lineage source hashing and correction-scope calculation through actual daily update completion. Immutable accepted entries carry their plans; changed entries and targets select fresh work. Completed acquisition endpoint/extent projections cross publication once. Changed source generations and cutoffs select fresh acquisitions. The serving migration regressions preserve legacy checkpoint capabilities across repeated metadata-only publications without reopening prices, recover an interrupted acknowledgement without repeating evaluation, and establish the new preceding boundary on append. These fixes do not close F15's unexercised cases or establish production throughput.

Converter publication regressions reject forced synchronization and all combinations of normal/report/failure destinations with metadata/action inputs and direct paths, hard links and symbolic links. Its current CSV regressions forbid sorting the shared accepted session grid again for any adjustment view.

  • Lineage fallback retains decoded pricing partitions; nested metadata needs share a completed containing interval; single-source observation selection skips unused multi-source preparation.

Live verification and limits

The subsequent authorized update with debug and without a separate plan run completed through the November 2, 2026 session in 1,256.5 seconds, with zero failures and zero pending work. It made 2,672 pricing and 449 metadata HTTP requests. The 2,560 late-bar probes occupied about sixteen minutes (76 percent of the run). All 9,422 append outcomes were unchanged; the live comparison selected one effective pricing correction. This same-cutoff run is not a controlled comparison with the earlier four-hour update.

The debug trace closed all 9,756 started spans without a reported error or abort. Raw traces, full runtime results, experiments and the original source inventory remain outside Git. They are observations of the exercised paths, not proof of every input or interleaving. The earlier four-hour run still lacks its own diagnostic trace.

The advancing-cutoff trace exposed F18–F23 and ended on requested SIGINT during dependency acquisition, with exit code 130 and no unclosed spans. That trace establishes the interrupted stage, not successful recovery. Recovery of the changes below is verified synthetically. A production restart completed journal recovery and compact selection, then exhausted six attempts on its first 3,386-symbol exact endpoint batch. An identical read-only request returned HTTP 504 with a backend timeout; smaller requests completed. A replay using the enlarged client timeout still received the backend failure before that timeout. The updater was interrupted cleanly before pricing or lineage publication. That attempt did not establish production completion; a controlled live throughput comparison remains unperformed.

A bounded read-only live MSGS check exercised exact endpoint planning in all eight retained views: sixteen requests returned sixteen matching rows. The revised daily first/latest check then used only the fully adjusted view: two requests returned two matching rows, with no pricing publication. This verifies those provider requests and comparisons, not universe throughput or every security.

An interrupted advancing-cutoff run checked 9,413 symbols: 9,354 matched, 26 differed and 33 had missing endpoints, with no request failures. Controlled read-only replays reproduced all 33 first-endpoint omissions in their original rosters; reduced rosters returned all 66 first/latest observations. The original run did not save response bodies. One controlled two-symbol case isolated companion-dependent suppression. The failed check also discarded completed comparisons, reproduced through a synthetic complete update. F25–F26 cover those defects and adjacent partial-publication cases. A subsequent debug update with these repairs completed pricing, lineage and serving through November 3, 2026, with zero failures and pending work and all 33 omissions recovered. Its trace closed every started span. Recovery and discovery now share the accepted catalogue, exact positive/negative asset lookups, completed corporate-action intervals, failures and conflict latches. Synthetic complete updates forbid a second catalogue or exact lookup, preserve ambiguous catalogue entries, and complete serving. New invocations obtain fresh observations.

The pricing transport contract distinguishes the client socket timeout from an earlier provider failure. Owning regressions exercise slow paginated responses without redundant requests, bounded timeout retries and preserved HTTP 504 classification: test_alpaca_pricing_download.py and test_alpaca_pricing_rate_limit.py. Retry errors and cooldowns are not exposed by the existing heartbeat; the debug request exit retains the attempt count but can omit a wrapped HTTP status. A healthy heartbeat alone does not establish provider progress.
